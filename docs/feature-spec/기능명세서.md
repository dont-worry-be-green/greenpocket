# 그린포켓(GreenPocket) 기능명세 및 MVP 우선순위 v2

## 1. 문서 목적

그린포켓 개발기획서의 기능 구조인 **A. 생활비 진단 → B. 절약 설계 → C. 혜택 관리 → D. 자립 저축** 순서에 맞춰 기능을 작업 단위로 정리한다. 본선 전 준비 기간 약 1주일을 전제로, 기능 수보다 다음 핵심 시연 흐름의 완성을 우선한다.

> 주거·청년 프로필 입력 → 고지서 데이터화 → 같은 지역 가구 평균 진단 → Green What-if → 지원제도 매칭 → 확인 금액 모의 적립
> 

### 우선순위

- **P0 - MVP 필수:** 핵심 시연 흐름을 구성하는 기능. 발표 환경에서 실제로 동작해야 한다.
- **P1 - MVP 권장:** P0 안정화 후 구현한다. 완성도와 차별성을 높이지만 시연에서 대체할 수 있다.
- **P2 - 후속 확장:** 해커톤에서는 목업이나 확장 계획으로 제시하고, 실제 서비스화 단계에서 구현한다.

### MVP 범위 원칙

- MVP는 **개별 전기 고지서형만 지원**한다. 관리비 통합형과 가스·수도 고지서는 개발 범위에서 제외한다.
- OCR은 전기 고지서 대표 양식 1종만 우선 지원하고, 반드시 직접 입력 대체 경로를 둔다.
- 비교 기준은 한전의 월·시군구별 가구 평균 전력사용량·요금 API 결과를 로컬에 저장해 사용한다. 공개 데이터에 없는 1인 가구·주거형태·평수 평균으로 표현하지 않는다.
- 지원제도는 외부 API를 연동하지 않고, 실제 조건을 사전에 확인한 **로컬 더미 데이터 3~5개**로 구현한다.
- 오픈뱅킹 테스트베드는 연동하지 않고 **모의 이체만 구현**한다.
- 예상 절감액·예상 혜택은 포켓 잔액에 합산하지 않는다. 확인된 금액만 적립 후보가 된다.

## B. 절약 설계

### B-1. Green What-if

| ID | 세부 기능 | 입력·처리 규칙 | 출력·완료 조건 | 우선순위 |
| --- | --- | --- | --- | --- |
| B-1-01 | 절감률 직접 입력 | 사용자가 원하는 전기 사용량 절감률을 숫자 입력 또는 슬라이더로 설정한다. 5%·10%·15%는 빠른 선택값으로 둘 수 있지만 입력값을 이에 한정하지 않는다. 유효 범위는 `0% 초과, 100% 미만`으로 검증한다. | 임의의 유효 절감률을 입력·수정할 수 있고 범위 오류가 안내된다. | P0 |
| B-1-02 | 목표 사용량 계산 | `목표 사용량(kWh) = 현재 사용량 × (1 - 절감률 ÷ 100)`으로 계산한다. 화면 표시에 필요한 소수점 처리 규칙을 통일한다. | 현재 사용량·절감률·목표 사용량이 함께 표시되고 경계값 테스트를 통과한다. | P0 |
| B-1-03 | 예상 다음 달 요금 | A-2-12 전기 요금 엔진에 목표 사용량과 적용 요금표 버전을 전달해 계산한다. `현재 청구액 × 절감률` 방식은 사용하지 않는다. 계절·가구 조건 등 엔진에 반영하지 못한 변수는 예상값 안내에 명시한다. | 적용 요금표 기준일과 계산 결과가 표시되고 동일 입력에 동일 결과가 반환된다. | P0 |
| B-1-04 | 예상 절감액 | `예상 절감액 = max(0, 현재 실제 청구액 - 목표 사용량 기준 예상 요금)`으로 계산한다. 현재 청구서와 예상 요금의 적용 조건이 다를 수 있음을 참고 문구로 표시한다. | 음수 절감액이 발생하지 않고 예상 라벨이 붙는다. | P0 |

## 핵심 비즈니스 규칙

1. **원화 우선:** 사용량보다 “같은 지역 가구 평균보다 약 4,200원을 더 지출했다”는 금융 영향을 먼저 보여준다.
2. **예상과 확인 분리:** What-if 결과와 예상 혜택은 참고값이며 포켓 잔액에 합산하지 않는다.
3. **적립 근거 제한:** 사용자가 확인한 절감 참고액과 실제 수령 완료 금액만 적립 후보가 된다.
4. **사용자 동의 필수:** 명시적 동의 없이 모의 이체를 실행하지 않는다.
5. **중복 적립 방지:** 하나의 고지서 또는 제도 수령 건으로 적립 후보와 거래를 한 번만 생성한다.
6. **첫 달 비교 제공:** 개인 이력이 없어도 같은 지역 가구 평균을 이용해 첫 달부터 진단한다.
7. **판정 근거 공개:** 제도 결과에는 매칭 사유와 더미 데이터 기준일을 함께 제공한다.
8. **불확실한 수치 미표시:** 공식 요금표·배출계수·비교 기준이 검증되지 않으면 숫자를 임의로 만들지 않는다.

### Green What-if 계산식

| 계산 항목 | 계산식·규칙 |
| --- | --- |
| 사용자 입력 절감률 | `r`, 단위 `%`, `0 < r < 100` |
| 현재 사용량 | 고지서에서 확인한 `U_current`, 단위 `kWh` |
| 목표 사용량 | `U_target = U_current × (1 - r ÷ 100)` |
| 예상 다음 달 요금 | `B_expected = ElectricTariff(U_target, tariff_version, billing_context)` |
| 예상 절감 사용량 | `U_saved = U_current - U_target` |
| 예상 절감액 | `S_expected = max(0, B_current - B_expected)` |

`ElectricTariff`는 적용 시점의 공식 주택용 전기요금표와 공식 반올림 규칙을 사용하는 함수다. 요금표 버전과 계산 조건을 결과와 함께 저장한다. 계절, 복지 할인, 부가 항목 등 MVP 엔진에서 지원하지 않는 조건은 계산 결과에 미반영 항목으로 명시한다.

## 확인이 필요한 사항

다음 운영 항목은 개발 착수 전에 팀이 직접 확인해야 한다.

- 한전 전력데이터 개방 포털 API 인증키 발급과 실제 최신 제공 월
- 본선에서 사용할 합성 전기 고지서 샘플과 OCR 성공률
- 외부 OCR 서비스 사용 시 이미지 보관기간·모델 학습 재사용·국외 처리 여부
- 적용할 공식 주택용 전기요금표 버전과 지원하지 않을 할인·계절 조건
- 본선 직전 로컬 제도 데이터의 접수 상태 변경 여부
