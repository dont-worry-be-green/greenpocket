## MVP 컷라인


### ① P0으로 실제 구현할 흐름

1. 데모 시작(이름 입력)과 5탭 내비게이션, What-if 홈 진입
2. 지역·주거 형태·평수 프로필 입력(2화면)과 마이페이지 조회·수정
3. 관리비 통합·개별 전기 고지서 OCR → 인식 결과 확인 → 3탭 수정 → 요약 확정 → 저장, 직접 입력 대체 경로, 항목 단위 중복 차단
4. 진단: 월 생활요금 합계, 지역 평균 비교(항목 탭·차액·6개월 추이), 빈 상태
5. What-if: 연동 전 → 연동 로딩 → 기준 사용량·요금별 비중 → 목표 미설정
6. 목표 정하기: 3개 세그먼트, 구간 칩, 목표 사용량·예상 절감액, 실천 미션 선택·합산 규칙, 합산 감축률·예상 마일리지, 저장
7. What-if 메인: 평가 기간 진행 카드, 전달 리포트 배너, 목표 카드, 월 감축률 계산
8. 전달 리포트 상세(결과·원인·처방·월별 막대)
9. 평가 결과 화면 → 마일리지 적립 확정 → 현금으로 바꾸기(외부 이동 → 복귀 시 전환 완료)
10. 혜택: 미참여 소개 → 연동 → 월 실천 현황·전체 항목 목록, 지급 완료 → 포켓 입금
11. 포켓: 잔액·최근 내역·전체 내역, 마일리지 전환, 출금 계좌·출금 신청(멱등)·출금 완료
12. 로딩·빈 결과·오류·재시도, 시드 적재, 데모 초기화

### ② P0 완료 후 추가 순서

1. 작년 동월 비교(A-3-06), 청구 월 선택(A-3-09)
2. 미등록 요금 탭(B-2-06), 절감률 환산(B-3-02), 오늘의 실천 체크(B-3-05)
3. 남은 기간 역산·실천 다시 고르기(B-4-08·09), 참여신청 배너(B-4-05)
4. 결산 알림 모달(B-5-01), 다음 평가 기간 전환(B-5-04)
5. 실천항목 상세·연간 한도(C-2-02·04)
6. 출금 내역·포켓 관리 화면(D-3-04·05)
7. 고지서 보관함·상세·삭제(A-2-12·13), 리포트 보관함(E-2-01)
8. 공통 UI 규칙 통일(COM-04), 개인정보 안내(COM-11)

### ③ MVP 명시적 제외 범위

1. 청년 지원제도 매칭·신청 관리와 청년 조건 입력 화면(결정 B-1로 온보딩 03 삭제)
2. 로그인·회원가입·소셜 인증(결정 A-4), 푸시 알림
3. 공식 요금표 기반 전기 요금 계산 엔진, 절감률 직접 입력형 What-if — 에코마일리지 구간 방식으로 대체
4. 고지서 기반 확인 절감 참고액 적립 — 덜 낸 요금은 성과로만 표시
5. 실제 외부 연동(에코마일리지·녹색생활실천 API, 참여신청·현금 전환 실제 처리) — 시드 기반 모의로 대체(결정 A-5)
6. 실계좌·오픈뱅킹·출금 계좌 본인확인(D-3-06, 결정 A-6) — 출금·전환은 모의 처리
7. 개별 수도·도시가스 고지서 OCR, 지역난방 — 수도·가스는 직접 입력, 지역난방은 배출계수 미공개로 미지원
8. 월별 리포트 자동 생성·다운로드(E-2-02), 금융습관 가이드(D-4), 서울 외 지역 에코마일리지

## 핵심 비즈니스 규칙

| No | 규칙 | 내용 |
|---|---|---|
| 1 | 원화 우선 | 감축률과 함께 줄어드는 요금 −44,090원, 지역 평균보다 +4,300원처럼 원화 영향을 먼저 보여준다. |
| 2 | 돈의 3단계 분리 | ① 예상 마일리지(평가 진행 중 추정치, What-if) → ② 적립된 마일리지(평가 확정, 아직 현금 아님) → ③ 그린포켓 입금(실제 잔액). 라벨과 색상으로 항상 구분한다. |
| 3 | 적립 근거 제한 | 포켓 잔액은 마일리지 전환 입금과 녹색생활실천 지급 완료 입금만 합산한다. 예상 마일리지·적립 예정 포인트·"덜 낸 요금"은 잔액에 더하지 않는다. |
| 4 | 사용자 동의 필수 | 명시적 동의 없이 마일리지 전환과 출금을 실행하지 않는다. |
| 5 | 중복 방지 | 평가 회차당 전환 1회, 전환은 1일 1회, 녹색생활실천 월 수령은 월 1건, 출금은 멱등키. 모든 입금·출금 거래에 고유 ID를 발급한다. |
| 6 | 기준선 이원화 | 진단은 같은 지역 가구 평균(+작년 동월), What-if는 에코마일리지 규칙대로 직전 2년 같은 기간 평균. 개인 과거 이력은 에코마일리지 연동값에 한해 사용한다. |
| 7 | 판정 근거 공개 | 미션 절감률에는 출처 수치·산출 근거·기관을, 마일리지에는 기준 요금·평가 기간 요금·줄인 금액을 함께 표시한다. |
| 8 | 불확실한 수치 미표시 | 배출계수·비교 기준이 검증되지 않으면 숫자를 만들지 않는다. 절감률은 모두 "추정" 문구를 붙이고, 달성 불가능한 역산 결과에 확정 표현을 쓰지 않는다. |
| 9 | 앱은 사용자 선택을 말없이 바꾸지 않는다 | 실천 재선택은 제안만 하고, 목표 구간 하향은 2회 연속 미달일 때만 제안한다. |
| 10 | 시차 규칙 | 월 페이스 판정은 진단 탭 고지서로, 최종 확정은 에코마일리지 누리집 기준으로 한다. 두 값의 차이는 화면에 명시한다. |
| 11 | 처리 중을 완료로 표시하지 않는다 | OCR·연동·전환·출금의 처리 중·실패 상태를 완료 화면으로 보여주지 않는다. 계좌번호 원문은 로그에 남기지 않는다. |

## Green What-if 계산식

| No | 계산 항목 | 계산식·규칙 | 쉬운 설명 (데모 숫자) |
|---|---|---|---|
| 1 | 기준 사용량·요금 | 항목 i ∈ {전기, 도시가스, 수도}의 6개월 기준 사용량 U_base,i, 기준 요금 B_base,i (에코마일리지 연동값, 직전 2년 같은 기간 평균) | 작년 이맘때 우리 집 성적표. 전기 1,340kWh · 268,000원 |
| 2 | 목표 절감률 | 선택 구간의 하한 r_i ∈ {5, 10, 15} (%) | 10~15% 칩을 고르면 r = 10 |
| 3 | 목표 사용량 | U_target,i = U_base,i × (1 − r_i ÷ 100) | 1,340 × 0.9 = 1,206kWh |
| 4 | 항목별 예상 절감액 | S_i = B_base,i × r_i ÷ 100 | 268,000 × 10% = 26,800원. 요금표 계산 없이 비례 |
| 5 | 온실가스 환산 | E = Σ U_i × f_i, f_전기 = 424 g/kWh · f_수도 = 332 g/㎥ · f_가스 = 2,240 g/㎥ (등록 항목만) | kWh와 ㎥를 탄소 그램이라는 공통 단위로 바꿔 더한다 |
| 6 | 합산 감축률 | R = (E_base − E_target) ÷ E_base × 100 | 전기 10%·가스 15%·수도 5% → 탄소 합산 11.322% |
| 7 | 지급 구간 | 5 ≤ R < 10 → 10,000M, 10 ≤ R < 15 → 30,000M, R ≥ 15 → 50,000M, R < 5 → 0 (1M = 1원, 연 최대 100,000M) | 11.322% → 30,000M |
| 8 | 월 감축률 | R_m = (E_base,m − E_m) ÷ E_base,m × 100. E_base,m = 직전 2년 같은 달 평균 환산, E_m = 진단 탭 고지서 환산 | 중간고사 점수. 7월 고지서 → 1% |
| 9 | 평가 기간 누적 | R_cum = (Σ E_base,m − Σ E_m) ÷ Σ E_base,m × 100 (등록된 달만) | 4~7월 합쳐 9% |
| 10 | 필요 월 감축률 | R_req = (r_target × 6 − Σ R_m) ÷ 남은 개월 | (10×6 − 9×4) ÷ 2 = 12% — 남은 두 달 매달 12% |
| 11 | 미션 절감률 | p_j = 출처 절감량_j ÷ (U_base,i ÷ 6) × 100, 상한 전기 30% · 수도 20% | 40kWh ÷ 223kWh = 18% |
| 12 | 미션 합계 | 같은 기기 그룹은 최대값 하나만: P = Σ_group max(p_j) | 냉방 26℃와 에어컨 1시간은 같은 에어컨 → 큰 것 하나만 |
| 13 | 녹색생활실천 예정액 | 예정액 = 유효 횟수 × 단가, 항목 상한 적용 | 전자영수증 24건 × 10원 = 240원 |
| 14 | 지역 평균 차액 | 사용자 금액 − 같은 지역 가구 평균 금액 | 43,200 − 38,900 = +4,300원 |
| 15 | 작년 동월 차액 | 올해 금액 − 작년 동월 금액 | 43,200 − 40,100 = +3,100원 |

> 계수는 에코마일리지 누리집 공개값을 쓰며, 계산 조건(기준 기간·등록 항목·계수 버전)을 결과와 함께 저장한다. 지역난방은 계수 미공개로 계산에서 제외한다(결정 C-11로 미지원 확정 — `utility_type` 은 전기·가스·수도 3종 유지).

**B-2-05 · 항목별 예상 절감액** — `P0` · `개발` · `BE` · 시스템 · 화면 WF-04

- **선행** 구간 선택
- **완료** 항목별 −26,800원 형식과 예상 라벨이 표시된다.

- **완료** 합산 카드(B-2-07)가 등록 항목만으로 계산된다.

**B-2-07 · 합산 감축률·예상 마일리지 카드** — `P0` · `개발` · `FE·BE` · 시스템 · 화면 WF-04 · WF-05

- **선행** 등록 요금 목표 존재
- **예외** 등록 요금만 합산

- **데이터** bankCode, accountNo, holder, isDefault
- **선행** 포켓 존재
- **예외** 계좌 없음 → 등록 유도
- **완료** 기본 계좌 배지가 하나만 표시된다.
- **비고** PK-07 시안 없음

**D-3-02 · 출금 신청** — `P0` · `개발` · `FE·BE` · 사용자 · 화면 PK-03

- **규칙** 출금 가능 잔액, 출금 금액 입력(전액 출금, +1만원 · +3만원 · +5만원 · 직접 입력 — 칩과 입력값 동기화), 받을 계좌 선택(기본 계좌 우선)·출금 계좌 변경, "출금 신청은 평일 09:00 ~ 18:00에 가능하며, 신청 후 영업일 기준 1~2일 내 입금됩니다" 안내, N원 출금하기 버튼을 제공한다. 0 초과·잔액 이하·정수를 검증하고 계좌 미등록을 막는다.
- **데이터** amount(int, 0<amount≤balance), accountId
- **선행** 잔액 > 0, 계좌 존재
- **예외** 잔액 부족·0원·계좌 없음 → 버튼 비활성 + 원인 표시
- **완료** 검증 실패 시 버튼이 비활성화되고 원인이 표시된다.

**D-3-03 · 출금 완료 (모의)** — `P0` · `개발` · `FE·BE` · 시스템 · 화면 PK-04

- **규칙** 멱등키로 중복 탭을 막고 출금 거래를 생성해 잔액에서 차감한다. 출금 신청이 완료됐어요! 화면에 출금 금액, 입금 계좌, 신청 일시, "영업일 기준 1~2일 내에 입금될 예정이에요" 안내, 그린포켓으로 돌아가기를 표시한다. 처리 중·실패를 완료로 표시하지 않는다. 실제 이체는 하지 않는다.
- **데이터** POST /pocket/withdrawals (idempotencyKey) → amount, requestedAt, expectedDate
- **선행** 검증 통과
- **예외** 중복 탭 → 1건만, 실패 → 완료 화면 금지
- **완료** 완료 후 잔액이 즉시 갱신된다.

**D-3-04 · 출금 내역** — `P1` · `개발` · `FE·BE` · 사용자 · 화면 PK-08

- **규칙** 출금 거래(금액·계좌·신청 일시·상태 requested · processing · completed · failed)를 목록으로 보여주고, 실패는 사유와 재시도 안내, 처리 중은 취소 정책 안내를 붙인다.
- **데이터** GET /pocket/withdrawals
- **선행** 출금 이력
- **예외** 빈 상태
- **완료** 잔액 차감 내역을 추적할 수 있다.
- **비고** 시안 없음

**D-3-05 · 포켓 관리 화면** — `P1` · `개발` · `FE` · 사용자 · 화면 PK-06

- **규칙** 그린포켓 정보(포켓 이름 "그린포켓" · 계좌·예금주·잔액, 계좌 복사), 출금 계좌 관리(D-3-01), 출금 내역(D-3-04), 출금 신청하기(D-3-02)를 한 화면에 모은다.
- **데이터** pocket, accounts[]
- **선행** 포켓 존재
- **예외** 복사 실패 → 토스트
- **완료** 포켓 메인 포켓 관리에서 진입한다.
- **비고** 시안의 포켓 이름 수정 UI는 제거한다(결정 C-2).

**D-3-06 · 출금 계좌 본인확인** — `P2` · `개발` · `BE` · 사용자 · 화면 PK-07

- **규칙** 은행·계좌 입력 후 본인 명의 확인(인증 세션)을 거쳐 저장하고 인증 상태를 배지로 표시한다. MVP에서는 구현하지 않는다(결정 A-6).
- **데이터** bank, account, holder, verifiedAt
- **선행** 본인 인증 세션
- **예외** 불일치·타임아웃
- **완료** 인증된 계좌만 기본 계좌가 된다.
- **비고** 후속 확장
